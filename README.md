# module8JournalCS370

For this project, I created and trained an intelligent pirate agent to navigate a treasure maze using deep Q-learning. The code that was provided gave me much of the environment itself: the maze, the pirate’s possible movements, the game-state setup, the experience replay structure, and the basic neural-network model. What I had to build was the training portion that actually made the pirate intelligent. The pirate was not given the correct path to the treasure. Instead, it had to make moves, receive rewards or penalties based on those moves, store what happened, and gradually learn which decisions were more likely to get it to the treasure. I had to work through how the agent would balance trying new moves with using the moves it had already learned were good, then train and test the model until it could consistently complete the maze. Unfortunately, my pirate never made it to the treasure. I even attempted to have it stop picking from only valid moves to see if it would provide a better result. The training outputs made it seem like it was overall better outcomes. However, the pirate agent still failed. I think that is due to the training starting in random grid points. many of its successful runs were like when it was on the right side of the maze and only had to move downward to the treasure. The final task placed the pirate at (0,0) and it almost always failed immediately given that there is only one valid move. If I were to do it again, I'd likely have it start at 0,0 for every training and only select a valid move. I think this is more akin to how a human would learn to navigate a maze. There is only really one to three valid choices, and we certainly aren't going to walk straight into a wall. we could navigate ourselves into corners, sure, but then our dopamine loops would likely punish us in a similar way as we have to turn around and find a new route. I think this likely would've created a more successful outcome for this particular experiment. It would have learned the actual maze itself and when given the opportunity would likely have learned the route to the treasure.

This project really brought together a lot of the things we covered throughout the course. At the beginning of the class, I understood AI mostly from the perspective of tools like ChatGPT, smart-home devices, advertisement systems, spec-driven development/agentic workflows, and some of the bigger things people talk about in the news and coding community. I understood that neural networks learned from data, but it was still fairly abstract. Working through the pirate project made it more real. The neural network was not just there to classify an image or spit out an answer. It was being used to estimate which action the pirate should take based on its current situation in the maze. Then reinforcement learning gave it the process to improve over time. The pirate tries something, sees whether it helped or hurt, and uses that experience to make a better decision later. It is obviously a small and controlled example, but it is the same general concept behind much more serious AI systems that need to make decisions in changing environments.

As a computer scientist, I think the real job is taking a problem or idea that may sound simple from the outside (because we are used to the manual process/model) and breaking it down into something a computer can actually understand and solve. In this case, “get the pirate to the treasure” sounds easy if you've ever done a corn maze or something similar, but the computer needs the maze represented as states, a list of valid actions, a way to measure whether an action was good or bad, a model that can learn from previous attempts, and testing to prove it is actually working. That is how I approach a problem now. I try to understand what the actual goal is, figure out what information the system needs, decide what approach makes sense, build it in smaller pieces, and test it until I understand where it is failing. In fact, I like to equate a lot of things back to dog training and the struggles I had with training my dog. First, the human needs trained. Even with personal projects I'm creating, I first need to build the mental computer; My own mind. For me to be effective as a software engineer, I have understand how to get there with my minds eye and internal calculations, visualizations, etc. Then, and only then can I provide the data in such a way that the system or an agent would be able to learn from just like I had. It's something I'm working on now by taking forecasting data running SWAN analysis for specific wave heights via bathymetric data, but also training a lightweight model to be able to look at the wind, tides, wave direction, etc. and give a quality score of the conditions. I now can look at the numbers and say "it'll be about this height, with some slight texture, but mostly fair conditions in the water." Getting a model to understand that requires the model to have the data sanitized in such a way where it predicts the outcome and tests it against human observation. The ethical part of AI matters too. A pirate maze is low stakes, but the same type of system could be used in healthcare, transportation, finance, hiring, or security. If the reward system is poorly designed, the AI can technically do what it was told while still producing a bad or harmful outcome. Heck even in my forecast example, if someone learns to trust my system, it could put them in a dangerous situation in the water if the system said it was good, but the conditions are too much for their skill level or physical ability. My responsibility to users and an organization would be to think about those outcomes before deploying something, protect data, be honest about the system’s limitations, test for unintended behavior, and make sure people still have control when the AI is making decisions that actually affect their lives.
